# 保存先と更新

## 保存場所

| 内容 | 配布用ZIP | Git / GitHubのソースZIP |
| --- | --- | --- |
| アプリ本体 | 展開したPaperMathフォルダー | 作業フォルダー |
| 専用Python・依存・キャッシュ | `%LOCALAPPDATA%\PaperMath\runtime` | 同じ専用runtime |
| 制作フォント・対応表・生成物 | `%LOCALAPPDATA%\PaperMath\data` | 作業フォルダー内の `assets` / `local-build` |

`Open_Paper_Math_Data.cmd` で制作データの保存先を開きます。配布用ZIPには `paper-math-distribution.json` が含まれ、制作データを本体から分離します。GitHubのソースZIPにはこのマーカーがないため、その作業フォルダー内に保存します。

セットアップは専用環境を作り、システムPythonやユーザー・システムのPATHを変更しません。通常起動は準備済みPythonを直接利用します。

## バックアップと旧開発版からの移行

OTFとLaTeX/PUA対応表を一組で保管します。完全なバックアップは、サーバーを終了して制作データフォルダー全体をコピーします。パネルのZIP書き出しもフォントと対応表の保管に使えますが、ZIPの自動読み込みは現在未実装です。

旧 `adobe-inline-math` の制作データを新しいソースフォルダーへ自動コピーする処理はありません。新しい本体で旧データを継続するには、PowerShellで旧フォルダーの絶対パスを明示してから起動できます。先に旧サーバーを終了します。

```powershell
$env:PAPER_MATH_DATA_DIR = 'D:\adobe-inline-math'
& 'D:\photoshop-inline-math\Start_Paper_Math.cmd'
```

この指定はそのPowerShellと子プロセスだけに適用されます。別の保存先に切り替える場合も、新しい対応表で古いフォントを上書きせず、対応するデータ一式を使います。

## 本体を更新する

サーバーを終了し、新しい本体を別のフォルダーへ展開して `Setup_Paper_Math.cmd` を実行します。配布用ZIPでは同じ制作データを引き継ぎます。ソースフォルダー利用では、上の明示指定かバックアップからのデータ移行が必要です。

UXPパネルのソースを変更した更新ではCCXの再インストールも行います。プラグインID `com.goldkiss2010.papermath` と管理フォントの内部識別は維持します。名称・アイコンは暫定で、後から見直す予定です。

データの初期化は、登録簿がない新規保存先だけで行います。登録簿がなく生成物だけ残る場合は、対応表のバックアップ復元を案内します。
