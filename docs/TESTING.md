# 検証と実機確認

## 自動試験

PythonとNode.jsを用意し、次を実行します。自動試験にPhotoshopとTeX本体は必要ありません。

```powershell
uv run --no-project --python 3.13.15 --with fonttools==4.67.0 python tools/run_partial_integration_tests.py
```

コード混在35例×LF/CRLF/CR、Python/JavaScriptの解析一致、部分成功、書式投影、復元、OTF/対応表、フォント出所、通知ZIP、保存先、CCX照合、配布ZIPを確認します。Windows専用テストはPowerShellの構文と、外部プロセスを模擬したインストール起動・分岐を確認します。Adobeへの実インストールは自動試験では行いません。

2026-10-15の分離版では、LinuxでPython 78件成功・Windows専用6件はスキップ、UXPのJavaScript 290件成功。実CCXのソース照合と配布ZIPの生成・全ファイルのハッシュも確認しました。Windows専用テストはこのローカル環境では実行していません。

配布ZIPを一時フォルダーへ展開し、外部の空データ保存先でLinuxの実TeX/SVG/OTFによる冷起動とAPI応答も確認しました。本体147ファイルは不変で、制作データは外部だけに生成されました。Windowsの初回導入を代替する試験ではありません。

CIはLinuxの統合試験とWindowsのランチャー試験を定義しています。CIでの実行結果とローカルの成功は別に記録します。

## 実機の報告（2026-10-15）

Windows 10 / Photoshop 27.4.0 / MiKTeX 25.12の一環境で、約36,000文字のコード混在原稿の変換・復元とPSD再オープンに成功報告があります。Pythonは3.13.15、fontToolsは4.67.0、PyMuPDFは1.28.2。LuaLaTeXの描画と全8書体の出所記録も確認されています。

UDT製CCXのソース照合後、UPIA経由の `-645` をCC直接呼び出しで回避し、ユーザーがCCXインストール成功と、その後のUDTなしでの使用成功を報告しました。各操作・再起動を個別に測定した試験票は未採取です。新しい代替ランチャーと、公開用フォルダーの冷起動は次の確認です。

## リリース候補の実機スモークテスト

1. 配布ZIPを新しいフォルダーへすべて展開し、セットアップを完了する。
2. 通常のCCXインストールを試す。確認画面が開かない環境で代替ランチャーを試す。
3. UDTの開発版をUnloadし、UDTを閉じる。
4. Startから起動し、Photoshopの「プラグイン」メニューからパネルを開く。
5. 制作フォントを作成し、`本文 $x_i^2$ と $\frac{a+b}{c}$。` を変換する。案内に沿ってOTFを導入して適用する。
6. 同じレイヤーでLaTeXへ復元し、本文とコードを保持することを確認する。
7. [混在サンプル](../examples/math-input/README.md)で改行・ブロック混在・保留の理由を確認する。
8. 表示名変更と通知付きフォントZIP保存を行い、OTFと対応表が揃うことを確認する。
9. PSD保存・Photoshop再起動後にパネルを開き、PSDの表示と往復を確認する。
10. 別のWindows環境で同じ手順を行う。空白・日本語を含む展開先でも確認する。

失敗した場合は、入力・Photoshop/CCの版・点検出力・パネルの診断を組み合わせます。機能の失敗と、Adobe側のCCX導入失敗は分けて記録します。
